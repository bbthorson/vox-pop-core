# Plan A — Lock the Core API Contract (pre-tester launch)

> **Status:** ready to execute · **Authored in:** `vox-pop-core` (public mirror) ·
> **Executes in:** private `vox-pop` repo (core-api routes + CI), except where noted.
>
> This plan is self-contained — it carries the context, the design rule, and the
> current surface audit so a session in the private repo can act without the
> originating conversation.

## Goal / done-bar

Make the **public consumer API surface final, documented, and CI-guarded** so we
can launch with testers and have devs build against a contract that won't churn
underneath them.

**Done when:**
- The documented surface contains only **primitives, queries, and public
  projections** (definitions below).
- Every endpoint description is a **contract**, not a workflow.
- "What is public" has a **single source of truth** + a **CI guard** that makes
  any surface change a deliberate, reviewed act.
- The audio primitives the embed example depends on are **in** the documented
  surface (today they are not — this is a real gap, not cosmetics).

## Design rule (the litmus test)

A route belongs in the **public contract** iff it is one of:

- **primitive** — CRUD over a core resource (users, prompts, replies, audio, auth).
- **query** — a read capability needing server-only state (search index,
  pagination cursors, filtering) a client can't rebuild from primitives.
- **public-projection** — an anonymous, public-safe read.

**Compositions** (an experience assembled from several calls — "inbox",
"onboarding", a dashboard) do **not** belong in the core API; they live in the
consumer / web-app BFF.

**Documentation corollary (Diátaxis):** Reference describes *one endpoint's
contract*. Multi-endpoint *workflows* live in how-to guides ("cookbooks"), never
in endpoint descriptions.

## How the surface is actually defined (mechanism)

- The spec is generated by `npm run gen:openapi -w @vox-pop/core-api`
  (`apps/core-api/scripts/generate-openapi.ts`), which bundles `app()` and calls
  `getOpenAPIDocument()`. Output is committed to `apps/core-api/openapi.json`.
- **Only routes registered via `app.openapi(createRoute({...}), handler)` on an
  `OpenAPIHono` appear in the spec.** Routes mounted with plain `Hono` are
  callable but invisible to the contract.
- `tags` / `summary` / `description` live in the `createRoute({...})` call. See
  `apps/core-api/src/adapters/inbound/rest/replies-feed.ts` for the canonical
  shape.
- Consequence: **"documented contract" = "instrumented via `createRoute` + tagged".**
  Promoting a route into the contract means converting it from plain `Hono`.
  De-scoping means leaving it plain `Hono`.
- Align with the existing migration note `specs/drafts/openapi-generation.md`
  (private) — the generator was piloted on `/users/*` and routes are being
  instrumented namespace-by-namespace.

> **Exposed ≠ documented.** Plain-`Hono` routes remain *callable* by any holder of
> a valid token even when undocumented. Plan A locks the *documented contract*.
> Actually *gating* composition routes from third parties is access-control work
> in **Plan B** (tier boundaries), not here.

## Work items

### A1 — Promote the audio primitives into the contract *(closes the embed gap)*
- Convert `audio.ts`, `audio-upload.ts`, `audio-upload-pending.ts` from plain
  `Hono` to `OpenAPIHono` + `app.openapi(createRoute({...}))`.
- **Decision:** tag as a new **`Audio`** family (recommended — proxy + uploads are
  cross-cutting) vs. folding into Prompts/Replies. Pick one and apply consistently.
- Reflect auth correctly: the `audio` proxy and `audio/upload-pending` are
  **anonymous** (no `requireAuth`) — the spec must not imply a bearer requirement.
- **Accept:** `gen:openapi` emits the audio paths; Scalar renders them; the
  endpoints referenced by the embed cookbook now resolve in the reference.

### A2 — Decide `resolve` / `rss` disposition
- `resolve` (`GET /api/v1/resolve/:handle`): document as a **public-projection**
  (public identity lookup) or leave undocumented. **Recommend: document.**
- `rss/parse`: per product note it's dormant profile-enrichment with no surface
  wired. **Recommend: keep code, leave undocumented** until it gets a surface
  (revisit in the connector model — potential RSS connector, in/out).
- **Accept:** decision recorded; spec matches it.

### A3 — Strip workflow prose from endpoint descriptions
- `replies-feed.ts`: `summary: 'Paginated reply inbox'` → contract language
  (e.g. `'List the viewer\'s replies (paginated, filterable)'`); rewrite the
  description to state the response shape / filters / cursor semantics, **not**
  the "inbox" workflow. The inbox framing moves to the Plan C cookbook.
- Sweep all `createRoute` descriptions for task/UX-surface language; keep them
  contract-only.
- **Accept:** no endpoint description names a UX surface or describes a multi-step
  task.

### A4 — Make OpenAPI tags the single source of truth
- Codify the rule in `apps/core-api` (a short README/`CONTRIBUTING` note or the
  generator header): a route is in the public contract **iff** instrumented via
  `createRoute` with a `tag` from the approved set.
- Fix the approved tag set: **Users, Prompts, Replies, Auth, Audio**. Add a
  top-level `tags` array (with one-line descriptions) via `OPENAPI_INFO` /
  `getOpenAPIDocument` if supported.
- **Accept:** every instrumented route carries an approved tag; nothing is
  instrumented without one.

### A5 — Public-surface snapshot + CI guard
- Commit a snapshot of the public **path+method** set (e.g.
  `apps/core-api/openapi.surface.json`, derived from `openapi.json`).
- Add a test (vitest) / CI step: regenerate the spec, extract the path+method
  set, diff against the snapshot, **fail on any difference**. Updating the
  snapshot must happen in the same PR → surface changes become deliberate.
- **Accept:** adding/removing/renaming a public endpoint fails CI until the
  snapshot is updated alongside it.

### A6 — Enforce dependency direction
- Add `eslint-plugin-boundaries` (or `dependency-cruiser`): `packages/core` and
  `packages/shared` **must not** import from `apps/*`; `apps/*` may import
  `packages/*`. This encodes "core is the foundation" without a repo split.
- **Accept:** a violating import fails lint/CI.

### A7 — Confirm compositions stay out of the contract
- Verify `people`, `organizations`, `screening`, `notifications`,
  `call-forwarding*` remain plain `Hono` (non-instrumented). No code removal —
  tier moves are Plan B.
- **Accept:** none of these appear in `openapi.json`.

## Acceptance checklist (the done-bar)

- [ ] Audio primitives appear in `openapi.json` + Scalar; embed cookbook links resolve.
- [ ] `resolve` / `rss` dispositions decided and reflected.
- [ ] No endpoint description contains workflow / UX-surface language.
- [ ] Approved tag set enforced; tags are the documented source of truth.
- [ ] Surface snapshot committed + CI diff guard green and proven (a deliberate
      change fails until the snapshot is updated).
- [ ] Dependency-direction lint green and proven (a bad import fails).
- [ ] Composition/app/internal routes confirmed absent from the contract.

## Out of scope (other plans)

- **Plan B** — connector boundaries: carve `apps/ivr` out of core-api; define the
  connector-config primitive (centralized settings + secret-by-reference);
  the `system/*` ingestion plane; tier moves for `people`/`organizations`/etc.
- **Plan C** — Diátaxis docs on the Starlight site (`vox-pop-core/docs/`):
  reference stays contract-only; add the How-to/cookbook section ("Build a reply
  inbox on the core") + the connector/topology explanation page.
- **Plan D** — repo split (post-launch, gated on this plan stabilizing the
  contract so `@vox-pop/shared` can be versioned cheaply). IVR first.
